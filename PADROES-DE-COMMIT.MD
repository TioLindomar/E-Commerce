# Padrões de Commits

Este documento descreve as convenções de prefixos para mensagens de commit no projeto.

- **feat**: Usado quando você adiciona uma nova funcionalidade ao código.
- **fix**: Usado quando você corrige um erro (bug).
- **refactor**: Mudanças no código que não adicionam funcionalidades nem corrigem erros, mas melhoram ou modificam a estrutura.
- **docs**: Atualizações na documentação (como arquivos README ou wikis).
- **style**: Mudanças de estilo e formatação (espaços, ponto e vírgula, etc) que não afetam a execução.
- **test**: Adição, atualização ou correção de testes unitários ou de integração.
- **chore**: Tarefas rotineiras, atualização de dependências ou arquivos de configuração (ex: .gitignore).
- **perf**: Um tipo especial de refatoração focado especificamente em melhorar a performance.
- **build**: Mudanças que afetam o sistema de build, empacotamento ou dependências externas.
- **ci**: Mudanças em arquivos e scripts de configuração de Integração Contínua (ex: GitHub Actions).
- **revert**: Reverte um commit anterior.
